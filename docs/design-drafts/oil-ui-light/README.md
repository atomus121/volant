## 推荐

如果只选一套进入 GPUI 实现，我推荐 **B · 白工位**。

理由是它和产品任务的耦合最直接：活动任务、速度、连接、进度和详情同时可见，暂停和打开目录就在当前对象旁；GPUI Kit 的 `TitleBar`、`Button`、`Input`、`Switch`、`Progress` 和普通列表已经足够，不需要为了视觉稿引入 DataTable。黑色窄轨提供了识别度，但白色仍占绝大部分画面。

想要更轻、更有“文件目录”识别度时选 A；想要把 Volant 的并发与分段能力作为产品记忆点时选 C。

## 组件映射

### A · 页边

- `TitleBar` + 顶部筛选栏。
- `Button` / `Input` 使用白色表面与黑色主按钮。
- 普通 GPUI 列表即可，选中项用行内展开，不需要 DataTable。
- 进度只使用一条黑色线；状态用 6px 点和文字，不铺彩色胶囊。

### B · 白工位

- `TitleBar`、顶部 tabs、`Button`、`Input`、`Switch`、`Progress`。
- 中央任务区按现有列表实现；任务量显著增长后再考虑 DataTable / VirtualList。
- 右侧检查器使用普通 GPUI 布局；8 连接刻度来自现有 `connections` 和 `speed`。
- 设置窗口沿用同一窄轨和控件尺寸。

### C · 传输轨

- 左侧队列和右侧当前任务舞台使用普通 GPUI 分栏。
- 8 条连接轨可用 `div` 分段或 GPUI canvas 绘制，不新增第三方图表依赖。
- `Progress` 只用于主进度；分片和连接轨作为任务专属可视化。
- 设置和新建下载使用更小圆角、更明确的水平规则线。

## 遵循两个组件库的方式

- 从 GPUI Kit 沿用系统化控件、语义主题、键盘焦点、AccessKit、Dialog 与 UI 测试能力。
- 从 Ely 借用白色开放画布、细灰规则线、克制状态色和“一个黑色主操作”的视觉关系。
- 生产实现只接入一套主题运行时。当前项目已经使用 GPUI Kit，因此 Ely 更适合作为视觉原则参考，而不是并列依赖。

## 动效

本轮是方向探索稿，按 `oil-ui` 的显式探索流程不加入交互和动效。

建议选定方向后补三个状态动效：新任务加入后列表让位、暂停/继续时进度轨与状态同步、详情或检查器切换时的约 160ms 内容淡入。都只表达状态变化，不使用入场编排。

## 验证

- 9 个画面均通过 Oil UI 截图工具在 1440×900 下实际渲染。
- 检查了 100% 画面，并对 A 设置窗口、B 主窗口抽查了 2 倍像素密度图；没有控制台错误、横向溢出或图片加载失败。
- 可读性检查已修正全部对比度问题。
- B 的新建下载被工具报告一次“卡片里套卡片”；这是把原生窗口外框识别成卡片，窗口内的探测结果本身需要独立边界，保留。
- 对比页生成器报告体积较大，属于其自包含 HTML 外壳，不是候选页面依赖过多。
