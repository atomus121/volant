# Volant · Impeccable 双主题方向稿

这一轮提供 3 个独立方向。每个方向都包含主窗口、设置界面和新建下载界面，并分别提供浅色与暗色主题；共计 18 个 1440×900 画面。

- [交互设计稿](index.html)：切换方向、窗口与浅/暗主题。
- [主窗口总览](main-overview.png)

- [新建下载总览](add-overview.png)

## 方向

### A · 制图 Draftline

`impeccable` 方向轮次分配的主方向。

- 世界：制图纸、测量尺、工程记录；落到界面时只保留精确的标尺、细线、等宽数字和明确的版心。
- 主角：当前正在下载的文件。
- 主动作：新建下载。运行中的暂停与打开目录紧邻当前任务，但不与新建争夺主按钮层级。
- 浅色：白色纸张、石墨文字、少量蓝色强调。
- 暗色：深蓝黑工作纸、白色标注、蓝色活动状态。
- 记忆点：进度条由连续测量刻度组成，速度与连接数紧贴同一条标尺。

### B · 时刻 Transit

- 世界：路线图与出发时刻表；保留清楚的起点、当前节点和终点。
- 主角：当前文件在队列中的位置。
- 主动作：暂停 / 继续当前下载。
- 浅色：白色、深灰、少量绿色用于活动线路。
- 暗色：碳灰底、浅灰文字、柔和绿色线路。
- 记忆点：当前任务不是普通进度条，而是一段有位置的路线。

### C · 档案 Folio

- 世界：文件索引与归档记录，强调下载完成后仍能被找到。
- 主角：当前选中的文件记录。
- 主动作：暂停 / 继续；新建下载仍然常驻但退到工具层。
- 浅色：白色纸张、近黑标题、低对比灰色分隔。
- 暗色：深墨色阅览面、暖灰文字、低饱和蓝作为进度指示。
- 记忆点：选中文件时，左侧索引与右侧文件页同步切换。

## 推荐

优先推荐 **A · 制图**。它既保留下载器需要的熟悉任务结构，又把 Volant 最独特的“并发分段传输”转成可读的标尺，而不是额外增加一排统计卡。

如果希望更快扫视队列，B 更适合；如果更重视下载完成后的文件管理，C 更适合。三套都可以保留，但应选择一套作为主系统，避免在同一产品中混用三个不同的结构隐喻。

## 两套主题的共同语义

| 角色 | 浅色方向 | 暗色方向 |
|---|---|---|
| 页面底色 | 白色 | 深石墨或深蓝黑 |
| 主文字 | 近黑 | 近白 |
| 次文字 / 元数据 | 深灰，保证 4.5:1 | 浅灰，保证 4.5:1 |
| 分隔线 | 低对比灰线 | 低对比浅线 |
| 主按钮 | 近黑按钮、白色文字 | 近白按钮、深色文字 |
| 进行中 | 方向专属强调色 | 同色相的更亮版本 |
| 成功 / 警告 / 错误 | 仅用于小面积状态 | 仅用于小面积状态 |

两个主题共用同一组件尺寸、圆角、间距和状态文案，不做两套布局。

## GPUI 映射

- `TitleBar`：保留原生窗口控制与拖动区域。
- `Button`：主操作为实心，高危险操作仍使用明确的确认流程。
- `Input` / `Select`：新建下载、设置中的路径与限速字段。
- `Switch`：剪贴板捕获、删除确认、做种等二元设置。
- `Progress`：只承担单条主进度；A 的标尺和 B 的路线均由普通 GPUI 元素组合实现。
- `Entity` / `Context`：主题切换和视图状态沿用现有 GPUI 生命周期，不建立平行状态源。
- 连接柱、路线节点和文件索引只是一层展示，不改动 `Cmd` / `UiEvent` 业务边界。

## 检查与限制

- 18 个窗口画面都在 1440×900 下实际渲染并逐组检查。
- 浅色以白色为主，暗色不是机械反相；两套都保留相同的信息层级与状态含义。
- 主内容在 100% 下可读，按钮和设置行的可点击区域保持稳定。
- 已有状态：下载中、等待、暂停、完成、失败。
- 当前设计稿未接真实 GPUI 数据；“新建下载”“暂停”和设置控件只表达状态，不代表已接入事件。
- 本轮是方向比较，未进入单一方向的完整交互、动效、独立 UX 走查和 `DESIGN.md` 固化。
- `impeccable` 的远端方向挑战目录不可达，因此方向轮次为降级模式：没有额外 challenger 或 Quality Bar 卡片；A 仍是脚本分配方向，B、C 为同事实包下的备选。
